# Physics Model and Validity

Status: **Draft for creator review** (DOCS-002, #8) · Plan version 0.2.0 · Decisions: [DECISIONS.md](DECISIONS.md) · Time rules: [TIMELINES.md](TIMELINES.md)

This doc states which physics the game treats as real, what is assumed or invented, and the numbers the code uses. Every number here is regenerated by [`physics/kerr_fixtures.py`](physics/kerr_fixtures.py) into [`physics/fixtures.json`](physics/fixtures.json). Code reads the JSON and never recomputes the physics at runtime.

## 1. What is real, what is assumed

## 2. The time-dilation model

Kerr black hole of mass `M` and spin `a`, Boyer–Lindquist coordinates, geometric units `G = c = M = 1`. For a body on a **prograde circular equatorial orbit** at radius `r`, the rate of its clock (`τ`) relative to a distant observer's clock (`t`) is [P1]:

```
dτ/dt = r^(3/4) · sqrt(r^(3/2) − 3 r^(1/2) + 2a) / (r^(3/2) + a)          (method A)
```

As an independent check, the script also contracts the equatorial Kerr metric with the orbit's 4-velocity, with orbital angular velocity `Ω = 1/(r^(3/2) + a)`:

```
dτ/dt = sqrt( −(g_tt + 2 g_tφ Ω + g_φφ Ω²) ),
g_tt = −(1 − 2/r),  g_tφ = −2a/r,  g_φφ = r² + a² + 2a²/r                    (method B)
```

The two methods agree to better than 1 part in 10⁵⁰ at every point used. The innermost stable circular orbit (ISCO) uses the standard closed form from [P1].

**Domain of validity.** Test body (planet mass ≪ black hole), exactly circular, equatorial and prograde, `r ≥ r_ISCO`, vacuum Kerr (no disk or other matter), `a < M`. Using the formula outside this domain, for example for a body hovering on rockets or on an eccentric orbit, is invalid.

**Units.** The ratios are dimensionless and independent of mass. Mass only sets the time scale: `GM/c³ = 492.55 s` for `M = 10⁸ M☉` (IAU nominal `GM☉/c³ = 4.925490947×10⁻⁶ s` [P5]).

## 3. How spin controls the effect

Slow-down factor at the ISCO, `S = dt/dτ` (from the fixture's reference table):

| Spin `a/M` | `r_ISCO / M` | `S` | Meaning |
| --- | --- | --- | --- |
| 0 (Schwarzschild) | 6.000 | 1.414 | 1 h on the planet = 1.4 h far away |
| 0.9 | 2.321 | 2.696 | |
| 0.998 (accretion limit [P2]) | 1.237 | 10.79 | 1 h = 10.8 h |
| 1 − 10⁻⁶ | 1.016 | 144.6 | 1 h = 6 days |
| 1 − 10⁻¹⁰ | 1.0007 | 3 133 | 1 h = 4.3 months |
| **1 − 1.33×10⁻¹⁴** | **1.00004** | **61 362** | **1 h = 7 years (the film)** |

The film's ratio is real general relativity, but only at a spin within about 1 part in 10¹⁴ of the maximum. You chose to keep it (D-12).

## 5. Corrections to the earlier draft

1. **The "Schwarzschild time ratio" claim is wrong as stated.** For any stable circular orbit around a non-spinning hole, the slow-down is at most `√2 ≈ 1.41` (at `r = 6M`). Factors like 61 000 need either a near-maximal spin (this doc) or an observer *hovering* just above the horizon on rockets, which is not an orbit and is not what the film shows.
2. **The waves are not "direct tidal force".** Tides stretch the planet; the proposed wave mechanism [P3] is the planet rocking within that tidal pull. This is speculative and is treated as tuned content, not physics output.
3. **The extreme spin was not flagged.** It is now listed as a speculative parameter (§1) and recorded as a deliberate choice (D-12).

## 6. Ranger transit (M1 approach)

Descent and ascent between Endurance and Miller are **route-table entries** `(ΔT, Δτ_Ranger)` in content data, labelled `tuned`. A physically derived trajectory (a geodesic integration through the strong-field region, possibly with a slingshot as [P3] describes) is out of scope for M1. If it is added later, the table format stays the same and only the values change.

## 7. Control assists (gameplay, not physics)

Docking and landing autopilot (mandatory for `LOCKED_SEQUENCE` segments), attitude stabilisation, a trajectory and time-cost preview before you commit to an action, and a "what this costs Romilly" readout during free-roam on Miller. Assists never change the physical rates; they only change what the player has to control.

## 8. Fixtures and tolerances

- `docs/physics/fixtures.json` is generated by `python3 docs/physics/kerr_fixtures.py` (standard library only, 60-digit decimals).
- `python3 docs/physics/kerr_fixtures.py --check` recomputes everything and fails if any value differs from the stored file by more than a relative 10⁻⁹. Run it in CI once the toolchain exists (#11).
- Domain code loads `game_rates_dtau_dT` as float64. It never evaluates the Kerr formulas (TIMELINES §1 arithmetic rule).
- `test_only.synthetic_ratio = 10` exists for unit tests and has no astrophysical meaning (TIME-001).
